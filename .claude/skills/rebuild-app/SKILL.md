# 重新打包应用技能

## 何时使用

- 用户要求重新打包 / 构建安装程序
- 代码有改动后需要生成新的安装包

## 第一步：确认打包环境

按顺序检查，任何一项不满足都先处理再打包：

1. **Node.js / npm**：`node -v` 和 `npm -v` 能输出版本号
2. **依赖已安装**：`node_modules` 存在（缺失 → `npm install`）
3. **Rust 工具链**：`cargo --version` 能输出版本号
4. **MSVC 编译器**：`where link` 或 `MSVC_BIN`（打包必须编译 Rust release）
   - 缺失 → 提示用户按项目 CLAUDE.md 说明设置环境变量
5. **磁盘空间**：检查剩余空间（release 编译产物较大，至少需 5 GB 左右空闲）

## 第二步：打包前跑单元测试（质检）

```bash
npm test
```

- **全部通过** → 继续打包
- **有失败** → 停止打包，把失败详情报告用户，由用户决定（修复后再打 / 坚持打包）

## 第三步：执行打包

```bash
npx tauri build
```

- **必须用后台方式运行**（`run_in_background: true`），打包需要 5~20 分钟
- 开始前明确告知用户："正在打包，release 编译较慢（约 5~20 分钟），完成后会告诉您"，期间不要频繁打扰用户
- 打包流程：编译前端（tsc + vite build）→ 编译 Rust release → 生成安装包

## 第四步：确认产物并复制到根目录

- **产物位置**：`src-tauri/target/release/bundle/nsis/` 下的 `.exe` 安装包
- 确认文件已生成（存在且大小 > 0）
- **复制到项目根目录**，覆盖旧的 `黑马记账APP.exe`（安装包保持最新版，方便用户找到）
- 同时告诉用户新安装包的确切文件名

## 第五步：告知用户

1. ✅ **打包完成**，安装包已复制到项目根目录
2. 使用方法：双击安装包即可安装/更新应用
3. 提醒：安装包覆盖旧文件，旧的未安装版本作废

## 注意事项

- **打包成功与否以真实输出为准**，未确认安装包生成前不得声称"打包完成"
- 打包失败 → 读取错误信息如实报告，判断原因（依赖缺失 / MSVC 环境 / 磁盘不足等），给出修复建议
- **项目目录移动过导致的缓存问题**：若报错含"failed to read plugin permissions ... 系统找不到指定的路径"且路径含旧目录名 → 删除 `src-tauri/target` 后重新打包（自动生成的构建产物，可安全删除，全量编译会更慢）
- 不修改任何业务代码来"迁就"打包问题
- 打包消耗大量 CPU 和磁盘，若用户需要同时做其他事情，告知打包会占用资源
