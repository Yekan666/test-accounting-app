# 启动应用技能

## 何时使用

- 用户要求启动 / 打开 / 运行应用查看效果
- 修改代码后需要验证界面（开发模式带热更新）

## 第一步：确认启动环境

按顺序检查，任何一项不满足都先处理再启动：

1. **Node.js / npm**：运行 `node -v` 和 `npm -v`，能输出版本号即可
2. **依赖已安装**：检查项目根目录是否存在 `node_modules` 文件夹
   - 不存在 → 先执行 `npm install`（解释：下载项目需要的依赖包，可能需要几分钟）
3. **Rust 工具链**：运行 `cargo --version`，能输出版本号即可（Tauri 后端需要）
4. **MSVC 编译器环境**（Windows）：编译 Rust 需要。检查方法：`where link` 或查看环境变量 `MSVC_BIN`
   - 缺失 → 提示用户：需要设置 MSVC 环境变量（参考项目 CLAUDE.md 中的说明），或引导用户安装 Visual Studio Build Tools 的 C++ 工作负载
5. **端口 5173 空闲**：Vite 默认使用 5173 端口。检查方式：`netstat -ano | grep 5173` 或直接尝试启动（启动失败时排查）
   - 被占用 → 找到占用进程，告知用户，不擅自杀进程

## 第二步：启动应用（开发模式）

```bash
npx tauri dev
```

- **必须用后台方式运行**（`run_in_background: true`），因为应用窗口打开后命令会一直运行，不会退出
- 启动过程中同时输出"正在启动应用，窗口出现后会告诉您"

## 第三步：确认启动成功

- **观察运行输出**（后台任务的输出文件），看到以下标志即成功：
  - `vite ready`（前端开发服务器就绪）
  - `Running ... target\debug\app.exe` 或 `Finished dev profile`（Rust 后端编译完成、窗口已启动）
- **成功** → 进入第四步告知用户
- **失败** → 读取错误输出，判断原因：
  - 依赖缺失 → 回到第一步处理
  - 编译报错（link.exe 找不到）→ 是 MSVC 环境问题，提示用户
  - **报错含"failed to read plugin permissions ... 系统找不到指定的路径"且路径含旧目录名** → 项目目录移动过，Rust 编译缓存（`src-tauri/target`）记录了旧路径。解决：删除 `src-tauri/target`（自动生成的构建产物，可安全删除），重新 `npx tauri dev` 全量编译（需几分钟）
  - 其他报错 → 把错误信息如实报告给用户，给出修复建议，**不掩盖失败**

## 第四步：告知用户

明确告诉用户：

1. ✅ **应用已经跑起来了**（窗口应该已经弹出）
2. 使用方法：关闭窗口即退出应用
3. 热更新说明：修改代码保存后，界面会自动刷新，不需要重启

## 注意事项

- **启动成功与否以真实输出为准**，未确认就绪前不得声称"已启动"
- 用户关闭应用窗口时，后台命令会正常退出（退出码 0），此时告诉用户应用已关闭
- 不要修改任何项目代码来"迁就"启动问题
- 首次启动 Rust 编译较慢（可能几分钟），期间如实告知用户在编译中，不要催促或假装已完成
